# 관상가 아솔 (GwangsangWebAPP)

**v2.8.0** (2026-09-02) · Streamlit 웹앱

사진 한 장으로 관상을 풀이해 주는 웹앱. 조선 팔도를 떠돌던 전설의 관상가
'아솔'이 얼굴을 보고 성별·나이대·직업을 짚어 준 뒤 관상 풀이를 들려준다.

- 배포: https://gwansang.ssirn.co.kr (svr3, Cloudflare 터널)
- AI 백엔드: **사내 LLM 서버** (OpenAI 호환 API, 비전 모델 `gemma3:27b`)

## 감정서는 두 단계다 (v2.8.0)

| | 분량 | 양식 | 언제 |
|---|---|---|---|
| 맛보기 | 600자 안팎 | `SHORT_FORM` — 5개 항목 | 버튼을 누르면 바로 |
| 전체 | 1200자 이상 | `PROMPT_FORM` — 15개 항목 | [전체 감정서 보기]를 누르면 |

⚠️ **맛보기 분량을 바꾸려면 양식(`SHORT_FORM`)을 고쳐야 한다.**
큰 양식에 "600자로 써라"라고만 지시했더니 1,600자가 나왔다. 항목이 열다섯 개라
한 문장씩만 써도 그 분량이 되기 때문이다. 지시가 아니라 양식이 분량을 정한다.

## 나이는 물어본다

사진만으로는 나이를 자주 틀린다(60대를 40대로 보는 일이 잦았다). 그래서
연대(10~90대)와 구간(초·중·후반)을 직접 고를 수 있게 했다.

- 고른 값이 있으면 **그 값으로 감정한다.**
- 아솔의 추정과 다르면 숨기지 않고 "아솔은 30대 초반으로 보았소만"이라고
  함께 보여 준다. 그래야 왜 물었는지 납득이 간다.
- 조사는 `_euro()` 가 받침을 보고 '로/으로'를 고른다.

## 결과는 버튼 블록 밖에서 그린다

`st.session_state` 에 담아 두고 버튼 블록 **밖**에서 그린다. 전에는 버튼 안에서만
그려서 화면을 다시 그리면(=[전체 감정서 보기]를 누르면) 결과가 통째로 사라졌다.

## 메일 발송 (`mailer.py`)

전체 감정서를 메일로도 보낸다. **SMTP 릴레이가 반드시 필요하다.**

서버(svr3)의 공인 IP 는 역방향 이름(PTR)이 없어서 직접 보내면 받는 쪽이
스팸으로 거르거나 거부한다(네이버는 25번 포트 자체가 막혀 있다). 릴레이를
쓰면 보내는 주체가 그쪽 서버가 되므로 정상 도착한다.

`app.env` 에 넣는다:

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=보내는계정
SMTP_PASS=앱비밀번호
SMTP_FROM=아솔 <asol@ssirn.co.kr>
SMTP_MODE=starttls        # starttls | ssl | plain
```

설정이 없으면 **보내지 않고 그렇다고 화면에 말한다.** 성공한 척하지 않는다.
남긴 주소는 발송 성공 여부와 무관하게 `data/emails.jsonl` 에 기록된다
(컨테이너 볼륨이라 이미지를 다시 구워도 남는다. `.gitignore` 로 저장소에서는 제외).

## 배포

```bash
git archive HEAD | ssh svr3 'tar x -C /data/sites/gwansang.ssirn.co.kr/app'
ssh svr3 'cd /data/sites/gwansang.ssirn.co.kr && docker compose up -d --build'
```

`.streamlit/config.toml` 에 **`browser.serverAddress` 를 절대 넣지 말 것.**
프론트엔드가 웹소켓 주소를 그 값으로 강제해서 터널 뒤에서는 화면이 영영
"연결 중"에 머문다. (예전에 Cloud 시절 주소가 박혀 있어 배포할 때마다 깨졌다)

## 알려진 것

- **인앱 브라우저 차단은 없다.** v2.8.0 에서 지웠다. `st.markdown` 으로 넣은
  `<script>` 는 브라우저 규격상 실행되지 않아 처음부터 동작한 적이 없고,
  화면 맨 위에 `}` 한 글자만 흘리고 있었다. 필요하면 새로 만들어야 한다.

## 실행

```bash
pip install -r requirements.txt
streamlit run streamlit_app.py
```

`.streamlit/secrets.toml` 에 아래 두 값이 있어야 한다. (이 파일은 `.gitignore` 로 제외됨)

```toml
LLM_BASE_URL = "https://llm.ssirn.co.kr/v1"
LLM_API_KEY  = "..."
```

## 변경 이력

### v2.7.0 (2026-09-02) — 생성 중 진행 표시

**문제**: 1200자 감정서는 30~70초가 걸리는데, 그동안 화면은 "장군신 소환 중..." 에서
아무 변화가 없어 **멈춘 것처럼 보였다.** 서버는 멀쩡히 GPU 를 돌리고 있는데도.

**조치**: 이미 스트리밍으로 받고 있었으므로, 받는 조각을 그대로 화면에 흘려준다.
- 진행바가 85% → 99% 로 차오르고
- `🖌️ GEMMA3 장군신이 감정서를 쓰는 중… 1,234자 · 28초`
- 지금 쓰고 있는 대목의 끝 160자를 커서와 함께 미리 보여 준다
- 화면 갱신은 **0.35초에 한 번**으로 제한(너무 잦으면 오히려 느려진다)

`llm_client.generate_with_image(..., on_progress=콜백)` 으로 붙였다.
콜백에서 예외가 나도 생성이 끊기지 않게 감쌌다.

**참고 — 이때 서버에서 있었던 일**: 같은 날 svr1 의 Ollama 가 GPU 를 놓치고
**100% CPU 로** 돌고 있었다(gemma3 가 약 3 tok/s, 첫 토큰까지 25초).
그래서 "gemma 를 불러도 안 온다" 는 증상이 겹쳐 보였다. 서버 쪽을 고친 뒤
같은 요청이 **첫 조각 0.8초 · 총 33.8초 · 2,623자** 로 끝난다.

### v2.6.0 (2026-09-01) — AI 백엔드를 사내 LLM 서버로 완전 교체

**무엇이 문제였나**

1. Google Gemini API 의존. 무료 할당량(429)을 자주 넘겨 "모든 장군신이
   휴식 중"으로 떨어지고, Hugging Face 대체 경로도 410 으로 죽어 있었다.
2. 윈도우에서 로컬 실행하면 앱이 화면을 그리다 말고 죽었다.

**왜 그랬나**

2번이 특히 고약했다. 콘솔 인코딩이 cp949 인데 `print("❌ ...")` 의 이모지가
cp949 로 인코딩되지 않아 `UnicodeEncodeError` 가 났다. 하필 그 print 가
`except` 블록 안에 있어서, **원래 에러를 보고하려던 코드가 스스로 터지며
진짜 원인까지 가려 버렸다.** 겉으로는 "요소 5개만 그리고 멈춤"으로 보인다.

**어떻게 고쳤나**

- `llm_client.py` 신규. OpenAI 호환 `/v1/chat/completions` 래퍼이며, 응답
  객체가 `.text` 를 그대로 갖도록 맞춰 기존 UI 코드 1,000여 줄은 손대지 않았다.
- Gemini · Hugging Face 경로 전부 제거 (`genai` 잔재 0건 확인).
- 파일 최상단에서 stdout/stderr 을 UTF-8 로 고정. 다른 import 보다 먼저 수행한다.
- 비전 모델만 사용. 관상은 사진을 봐야 하므로 텍스트 전용 모델은 쓸 수 없다.

**모델 선정 근거 (실측)**

서버의 7개 모델 중 이미지를 볼 수 있는 것은 2개뿐이었다.

| 모델 | 결과 |
|---|---|
| `gemma3:27b` | 24초에 정상 응답, 요구 형식 4개 항목 모두 정확 → **채택** |
| `qwen3-vl:32b` | 126초를 끌다가 HTTP 524 → 제외 |

524 는 서버 앞단 Cloudflare 가 원본 응답을 기다리다 끊은 것이다. `qwen3-vl` 은
thinking 모드로 사고과정(`reasoning`)을 길게 뱉느라 느리다. 되살리려면 thinking
을 끄는 옵션을 먼저 확인해야 한다.

이 제약 때문에 함께 손본 것:

- 읽기 타임아웃 300초 → **90초**. Cloudflare 가 약 100초에 끊으므로 그 전에
  포기해야 다음 모델로 넘어간다. (기존 300초 설정이 "얼굴 기본 정보 분석 중"
  에서 하염없이 멈춰 있던 직접 원인이었다.)
- 스트리밍 수신으로 전환. 첫 조각이 곧바로 흘러나오므로 524 를 피할 수 있다.
  스트리밍 결과가 비면 일반 방식으로 자동 재시도한다.

**어떻게 검증했나**

- 웹소켓으로 실제 세션을 붙여 스크립트를 실행 → `FINISHED_SUCCESSFULLY`,
  요소 12개 렌더, 예외 0건.
- `PYTHONIOENCODING` 없이 실행해도 이모지 로그가 정상 출력됨을 확인
  (cp949 크래시 재발 없음).
- 앱 소스에서 실제 관상 프롬프트를 그대로 추출해 서버에 태운 결과,
  `성별 / 나이대 / 현재 직업 / 어울리는 직업` 4개 항목이 형식대로 반환됨.

**남은 것**

- 실사용 사진으로 긴 본문(1200자 이상) 생성까지의 최종 확인.
- `qwen3-vl:32b` thinking 비활성화 검토.
